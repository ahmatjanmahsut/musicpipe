## 3. 认证机制(v5 统一账号体系,2026-10-19)

- **一套账号,两个入口**:所有账号都在 users 表(密码 'salt16hex:scrypt64hex')。App 走 /api/v1/accounts/register|login;Web 控制台走 /api/auth/login {username,password},**仅 role=admin 可登录控制台**(非管理员 403 admin_only,App 端不受影响)。旧「单密码控制台」(settings.console_password + test1234)已整体废止。
- **控制台初始化语义变化**:/api/auth/setup 仅当 users 表为空时可用(创建首个 admin,密码≥6位);已有账号时返回 400 '已有账号，请直接登录'。/api/auth/status → {needsSetup:!hasAnyUser(), loggedIn, username, role}。控制台登录限流 20 次/15 分钟(IP)。
- 会话表 sessions(token, created_at, expires_at, user_id);v5 迁移已删除全部旧无主会话(user_id='')——现存会话一律绑定 users.id。sessionUser(req) 仍保留 console 兼容分支(历史语义),但线上已无此类会话。
- 令牌 = 24 字节随机 hex,库中只存 sha256;有效期 30 天。
- 三种携带方式(authHook 按序识别,**App 与 Web 控制台通用**):
  1. Cookie `mp_session=<token>`(Web 控制台登录自动下发)
  2. `Authorization: Bearer <token>`(App 首选)
  3. `?token=<token>` 查询参数(media3 播放器/Coil 图片/APK 下载等无法带 Header 的场景)
- WebSocket /ws 同样认 cookie 或 ?token=。
- 放行白名单(无需登录):/api/auth/*、/api/v1/accounts/register|login、静态资源。
- **authHook 权限强化(v5,堵漏洞)**:此前任意有效会话可打全部 /api/*;现在**控制台域(非 /api/v1/* 的 /api/*)额外要求 sessionUser.role==='admin'**(或 console 会话),否则 403 {error:'forbidden'}——App 普通用户 token 从此无法触达控制台 API(搜索/任务/音源/设置等)。/api/v1/* 网关域维持「有效会话即可」+端点内 needAdmin/needUser 分级。
- **已移除(破坏性变更)**:网关旧认证三件套 POST /api/v1/auth/login|logout、GET /api/v1/auth/check(单密码制,App 从未使用,grep 确认无引用)。
- 权限分级:
  - **needAdmin**:role=admin → 用户管理、发布管理。
  - **needUser**:任意有效会话 → latest/download。
  - 守卫:不能删/降级自己(self_delete/self_demote),不能移除最后一个 admin(last_admin)。
  - 删除用户会级联删其 sessions(令牌即刻失效)。

### 10.5.1 音质嗅探:不让非音频内容进入曲库

**背景**:用户反馈"音质自动时提示校验失败:无法识别的音频头 / 文件头(mp3)与扩展名(flac)不符"。

**实测机制**(曲目「顺流逆流」kw / songmid 211909578,该曲目只有 128k):

| 请求 | 结果 |
|---|---|
| 直接请求音源 `format=flac` | 返回纯文本 `refuse request!` |
| 服务端管线 `quality=flac` | 落盘文件前 12 字节 `162e0f2637634d4c52645465` —— 非音频、非文本,是兜底返回的加密/压缩流 → 校验必失败 |
| 服务端管线 `quality=128k` | 正常完成,`陈佳/似是故人来/顺流逆流.mp3` **3,834,555B** |

**改动**:

| 文件 | 改动 |
|---|---|
| `src/sources/adapter.js` | 新增 `export async function sniffAudioType(url)`(Range: bytes=0-2047 / 12000ms / UA MusicPipe)+ `export function sniffBuffer(buf)`(fLaC→flac, ID3→mp3, OggS→ogg, RIFF→wav, `buf.slice(4,8)==="ftyp"`→m4a, `0xFF&0xE0`→mp3, 否则 null) |
| `src/downloader/runner.js` | import 加 `sniffAudioType`;在 `var ext = q2ext(quality)` 之后插入嗅探:能识别且与推导不符 → 纠正 `ext`+`quality` 并记 `quality_override` 事件;识别不出 → 交给 `checkMagic` 判失败。**本轮再把失败文案改为可操作**:嗅探与 checkMagic 双双判非音频时抛「该曲目没有 X 音质的资源,请把音质改成「自动」或 128kbps 后重试」并记 `quality_unavailable` 事件 |
| `src/downloader/tagger.js` | `checkMagic` 增补 `ftyp`→m4a、无法判定时对 mp3 放行;family 表 {m4a:[m4a,aac,mp4], mp3:[mp3], flac:[flac], ogg:[ogg], wav:[wav]} |

**部署踩坑(务必记住)**:嗅探最初写进了 `.tmp/router-live\{adapter,runner}.js` —— 那是**扁平旧副本**,
容器真正运行的是 `src/sources/adapter.js` 与 `src/downloader/runner.js`。改错文件导致"代码明明改了却不生效"。

脚本：`mk110.mjs`（`crypto.scryptSync(pw, salt, 64)` 拼 `salt:hash` 写入 `users`）、`up110.ps1`（multipart 上传）、`ver110.ps1`（回读校验）、`clean110.mjs`（删除临时账号并打印终态）。
每版都核对 `users` 终态只有 `demo` 一条 —— 本轮同样通过。
